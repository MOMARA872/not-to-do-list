## Spacing Scale

Declared values (multiples of 4, matching Flutter `SizedBox` / `EdgeInsets` patterns already in use):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4dp | Icon gaps, caption-to-content gap (e.g. `SizedBox(height: 4)` in `AvoidedTodayCard`) |
| sm | 8dp | Between chips, compact inline spacing |
| md | 16dp | Default content padding (cards, screen horizontal padding, tile internal padding) |
| lg | 24dp | Screen horizontal padding for full-width copy regions (e.g. pause screen `horizontal: 24`) |
| xl | 32dp | Section spacer between ListView sections |
| 2xl | 48dp | Major screen-level top/bottom breathing room |
| 3xl | 64dp | Not used in Phase 6; reserved for future layout needs |

**Exceptions:**

- `SizedBox(height: 12)` between FABs on HomeScreen — existing established spacing; do not touch.
- Touch targets for all tappable tiles must be at least 48dp tall (Material 3 `ListTile` default satisfies this automatically).
- `SegmentedButton` for theme selector: height follows M3 default (40dp); do not override.

Inherits `AppTheme._textTheme` (Phase 2 lock). Phase 6 adds no new font sizes or weights. All roles below map to Material 3 `TextTheme` roles used throughout the existing codebase:

| Role | M3 TextTheme Role | Size (M3 default) | Weight | Line Height | Usage in Phase 6 |
|------|-------------------|-------------------|--------|-------------|------------------|
| Display | `headlineMedium` | 28sp | 400 (regular) | 1.29 | Settings section header text if needed; not used in Phase 6 |

## Color

Phase 6 inherits the existing `AppTheme` color system. No new color tokens are introduced. The theme selector (SETT-04) controls `ThemeMode` brightness only — it does not change the color seed.

| Role | Token / Source | Value (Light mode fallback) | Usage |
|------|---------------|----------------------------|-------|
| Dominant (60%) | `colorScheme.surface` | `#FFFFFF` (light) / `#1A1C19` (dark) | Screen backgrounds, Scaffold body, Settings ListView background |
| Secondary (30%) | `colorScheme.surfaceContainerLow` / `Card.outlined` | Near-surface tint | Section header backgrounds, `Card.outlined` used for dashboard cards |
| Accent (10%) | `colorScheme.primary` (seed: `Color(0xFF2D6A4F)`) | Deep forest green derived from Material You or static seed | Reserved exclusively for: primary FAB background, `FilledButton` fill, `SegmentedButton` selected segment, `ListTile` leading icon on active/focused state |
| Destructive | `colorScheme.error` | M3 red tonal | Reset button in AlertDialog only. `FilledButton.tonal` styled with error color. No other use. |

**Accent reserved for (explicit list):**
1. Primary FAB (`+ Add app`) background — existing, do not change
2. `FilledButton` fill (e.g. "I understand — open Settings" in onboarding) — existing
3. Theme `SegmentedButton` selected segment fill — new in Phase 6
4. `ListTile` leading `Icon` on the active/focus state — M3 automatic, do not override

**Destructive reserved for:**
- Reset AlertDialog confirm button only. No other element in Phase 6 uses `colorScheme.error`.

**Dynamic Color:** `DynamicColorBuilder` overrides the static seed on Android 12+ via Material You wallpaper seed. Phase 6 does not modify this behavior. The theme selector switches `ThemeMode` brightness, and `DynamicColorBuilder` continues to supply both `lightDynamic` and `darkDynamic` ColorSchemes.

## Interaction Contracts

### Settings hub (`/settings`)

- Tap on any navigation tile (`chevron_right` trailing): push named GoRoute, `context.go(route)`.
- Tap on Reset tile: show M3 `AlertDialog` (blocking — no route push).
- `SegmentedButton` selection on Appearance tile: immediate `ThemeMode` switch via `ref.read(themeModeProvider.notifier).set(value)`. Animation: M3 default segment transition (~200ms).
- Tap Export tile: navigate to `/settings/export` where the export intent is triggered.
- Back navigation: standard Android back button / AppBar back arrow.

### Theme switcher

- Three segments: `[Light | Dark | System]`.
- Single-select; at most one segment active at all times.
- Default on first install or post-reset: `System` selected.
- Selection persists immediately to `shared_preferences` key `theme_mode` (0=system, 1=light, 2=dark).
- `MaterialApp.router`'s `themeMode:` updates via `ref.watch(themeModeProvider)` — theme change takes effect on the next widget rebuild frame (no restart required).
- No loading indicator: the Riverpod rebuild is synchronous after the prefs write resolves.

### Export flow

1. User taps Export data tile → navigated to `/settings/export`.
2. On `/settings/export`: user taps "Export all data" tile.
3. App launches `ACTION_CREATE_DOCUMENT` intent with MIME type `application/zip` and suggested filename `not-to-do-list-export-YYYYMMDD-HHMM.zip`.
4. Android file picker opens (system UI — outside app scope).
5. On user confirms location: app writes ZIP (5 CSVs + `data.json`), shows a `SnackBar` on success.
6. On failure (I/O error): show `SnackBar` with error message (see Copywriting).
7. Export is one-shot; no progress indicator required for the expected small data volumes in v1.

### Reset flow

1. User taps Reset data tile on Settings.
2. `AlertDialog` appears with exact copy from Copywriting section below.
3. Cancel button is default-focused (first tabbable element). Tapping Cancel: dismiss dialog, return to Settings.
4. Reset button: execute `Drift transaction (delete all tables) + SharedPreferences.clear()` → `context.go('/onboarding/welcome')`.
5. No loading indicator: deletion is fast on expected data volumes.
6. After reset, GoRouter rebuilds from `/onboarding/welcome` because `onboarding_complete` is cleared.

### Privacy Policy screen (`/settings/privacy`)

- Renders `PRIVACY.md` content (bundled asset or pre-rendered constant — planner decides).
- Read-only scrollable view.
- No interactive elements beyond back navigation.
- `AppBar` with back arrow, title "Privacy Policy".

### Accessibility disclosure screen (`/settings/disclosure`)

- Reuses `AccessibilityStep` (read-only, from Settings context — no "I understand — open Settings" CTA needed since the user is already past onboarding).
- Implementation option: wrap `RationaleScreen` with `onSkip: () => context.pop()` and no `onPrimaryCta` (or a "Close" label that pops). Planner decides exact wrapping.
- The 5 verbatim disclosure phrases MUST remain unchanged (enforced by `prominent_disclosure_test.dart`).

## Screen-Level Layout Specs

### `SettingsScreen` (`/settings`)

```
Scaffold
  AppBar
    title: "Settings"
    centerTitle: false
    leading: back arrow (auto from GoRouter)
  body: ListView(
    padding: EdgeInsets.symmetric(vertical: 8),
    children: [
      // Section: Reminder
      _SectionHeader("Reminder"),
      ListTile(reminder time tile)    // nav → /settings/reminder

      // Section: Appearance
      _SectionHeader("Appearance"),
      ListTile(                       // inline SegmentedButton
        title: Text("Theme"),
        trailing: SegmentedButton<ThemeMode>([Light | Dark | System])
      )

      // Section: Data
      _SectionHeader("Data"),
      ListTile(export data tile)      // nav → /settings/export
      ListTile(reset data tile)       // action → AlertDialog (error color)

      // Section: Privacy
      _SectionHeader("Privacy"),
      ListTile(privacy policy tile)   // nav → /settings/privacy
      ListTile(accessibility disclosure tile) // nav → /settings/disclosure

      // Section: About
      _SectionHeader("About"),
      ListTile(about tile)            // display only
    ]
  )
```

Section headers: `Padding(padding: EdgeInsets.fromLTRB(16, 16, 16, 4), child: Text(label, style: tt.labelSmall.copyWith(color: cs.primary, letterSpacing: 0.8)))`. This matches M3 section label convention used in Android Settings.

### `HomeScreen` AppBar change

Current AppBar actions: `[IconButton(Icons.notifications_outlined)]`

Phase 6 adds settings icon to actions list. Updated actions order:
`[IconButton(Icons.settings), IconButton(Icons.notifications_outlined)]`

Settings gear is leftmost in the actions row (rightmost visually after the title, then notifications). Both icons use `Icons.*_outlined` style for visual consistency.

### Reset `AlertDialog`

```
AlertDialog(
  title: Text("Reset all data"),
  content: Text("This deletes every entry, streak day, pause event, and check-in. This cannot be undone."),
  actions: [
    TextButton(child: Text("Cancel"), onPressed: () => Navigator.pop(context)),
    FilledButton(
      style: FilledButton.styleFrom(
        backgroundColor: colorScheme.error,
        foregroundColor: colorScheme.onError,
      ),
      child: Text("Reset"),
      onPressed: _executeReset,
    ),
  ],
)
```

Cancel is listed first (default-focused per D-13). Reset is second. No `autofocus: true` needed on Cancel in M3 AlertDialog since it is the first action.

## Accessibility

- All `IconButton` widgets must have `tooltip` set (used as semantic label on Android TalkBack).
- `SegmentedButton` segments use their label text as semantic labels — no additional `Semantics` wrapper needed.
- `ListTile` with `onTap` carries implicit `button` semantics in Flutter. No override needed.
- Reset `AlertDialog` Cancel button must be reachable before Reset button in focus order (listed first in `actions`).
- `ListTile` for Reset uses `iconColor: cs.error` and `textColor: cs.error` for color-only distinction — the word "Reset" and the `Icons.delete_outline` icon together provide non-color redundancy for color-blind users.
- Minimum touch target: 48dp — satisfied by `ListTile` and `IconButton` defaults.
