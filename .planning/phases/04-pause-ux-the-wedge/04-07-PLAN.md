# Plan 04-07 — Wave 3: Flutter pause-screen UI + PauseController + pause_events writer

<objective>
Ship the Flutter UI half of the wedge — the screen the user sees. D-01..D-08 lock every visual + copy decision; this plan implements them faithfully.

The plan also ships:
- **PauseEventDao** + **PauseEventRepository** — the SOLE writer to `pause_events` (D-13). Phase 1's schema is unchanged; this plan registers the DAO with `app_database.dart`'s @DriftDatabase daos: list (which DOES re-run Drift codegen — the only file that does in this plan).
- **PauseController** — hand-written Riverpod AutoDisposeNotifier owning cooldown timer + outcome resolution.
- **3 widget files + 1 page** — modular per D-04/D-05/D-07 to keep each <100 lines.

Per CONTEXT specifics:
- Cooldown values: exactly `{1, 3, 5, 10}` minutes → `cooldownChosenSeconds` `60 / 180 / 300 / 600`.
- Outcome map: `0 = cooldown-completed`, `1 = cancel`, `2 = use-anyway`.
- `cooldownChosenSeconds` non-null when a chip was tapped (even mid-cooldown Cancel); null only when Cancel without ever picking a chip.
- D-07 confirmation card: literal `"✓ Cooldown complete"`, 1500ms hardcoded.
- D-13: insert-at-session-end (planner pick — see <objective> rationale below) — single INSERT with the final outcome, NOT insert-at-start + UPDATE-by-id.

D-13 planner choice (insert-at-end vs insert-at-start): **insert-at-end**. Rationale: insert-at-start with UPDATE-by-id has a race condition if PauseActivity is killed mid-cooldown — the row exists with `outcome = null` (or a stub outcome) and the cumulativeTotalsProvider's `WHERE outcome IN (0, 1)` skips it correctly, but the row pollutes the table. Insert-at-end has cleaner semantics: every row in pause_events corresponds to a completed session (cooldown ended OR user explicitly clicked Cancel/Use anyway). Activity-death-mid-cooldown means no row written — acceptable v1 trade-off per CONTEXT deferred line 217 ("Resume cooldown across activity death — acceptable v1 trade-off").

Per CD-02: Use anyway is enabled IMMEDIATELY on screen load — no after-cooldown gating, no rate-limit. Hard entries already omit Use anyway entirely (PAUS-09).

Per CLAUDE.md "Surgical Changes": Phase 1's pause_events_table.dart is BYTE-IDENTICAL after this plan (only the DAO registration in app_database.dart is augmented). Phase 3's cumulative_totals_provider.dart is BYTE-IDENTICAL — outcome=2 exclusion is preserved by construction.

Per Karpathy "Simplicity First": each widget is single-responsibility. The PauseController is a single hand-written notifier (no Bloc, no streams beyond Riverpod's own). Total new code: ~600 lines across 10 files.

This plan depends on Plan 04-05 (Intent contract — packageName + entryId + blockMode arrive at PauseScreen via the GoRouter route Plan 04-08 wires). Runs in parallel with Plan 04-06 within Wave 3 (zero file overlap — 04-06 owns Kotlin PauseActivity; 04-07 owns Dart UI).

Output: 10 new Dart files + Drift codegen rerun on app_database.dart + 5 Plan 04-01 stub tests flipped from skip to pass.
</objective>

**Step 2 — Create `lib/data/repositories/pause_event_repository.dart`:**

```dart
import 'package:drift/drift.dart';
import 'package:not_to_do_list/data/database/app_database.dart';
import 'package:not_to_do_list/data/database/daos/pause_event_dao.dart';

/// Single-writer seam for pause_events (D-13).
///
/// outcome: 0 = cooldown auto-completed; 1 = Cancel; 2 = Use anyway.
/// cooldownChosenSeconds: null only when Cancel was pressed without ever
/// tapping a cooldown chip (CONTEXT specifics line 193).
class PauseEventRepository {
  PauseEventRepository(this._dao);

  final PauseEventDao _dao;

  Future<int> insertOutcome({
    required int entryId,
    required String packageName,
    required DateTime triggeredAt,
    int? cooldownChosenSeconds,
    required int outcome,
  }) {
    assert(outcome >= 0 && outcome <= 2, 'outcome must be 0, 1, or 2');
    return _dao.insertEvent(
      PauseEventsCompanion.insert(
        entryId: entryId,
        packageName: packageName,
        triggeredAt: triggeredAt,
        cooldownChosenSeconds: Value(cooldownChosenSeconds),
        outcome: outcome,
      ),
    );
  }
}
```
