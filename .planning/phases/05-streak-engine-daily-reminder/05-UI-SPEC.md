Material 3 dynamic color scheme seeded from `Color(0xFF2D6A4F)` (deep forest green). `DynamicColorBuilder` in `app.dart` provides harmonized scheme on Android 12+; static fallback on Android 10/11.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `colorScheme.surface` / `colorScheme.background` | Screen backgrounds, Scaffold body |
| Secondary (30%) | `colorScheme.surfaceContainer` / `colorScheme.surfaceContainerHighest` | Home list tile background (`tileColor: cs.surfaceContainer`), card surfaces, entry detail sections |
| Accent (10%) | `colorScheme.primary` | Reserved for: active streak badge flame text, Submit button fill on `/checkin`, time picker confirm button, 4-left-border on highlighted dashboard rows (existing) |
| Destructive | `colorScheme.error` | No new destructive actions in Phase 5 — error color reserved for existing delete-entry button (Phase 2 carry-forward) only |

Accent reserved for (explicit list — Phase 5 additions only):
1. Submit button fill on `/checkin` screen (`FilledButton` = primary by M3 default)
2. Yes toggle selected state on `/checkin` row (`SegmentedButton` selected segment = primary)
3. Reminder time picker confirm action

Accent NOT used for:
- Streak badge flame emoji (rendered as Unicode character, not tinted)
- Day-status dots in calendar grid (4-state semantic colors defined below)
- Banner backgrounds (amber tokens only — see NOTF-07 banner below)

### 4-State Day-Status Color Contract (STRK-04 / D-07)

These are semantic colors, not M3 role colors. They are fixed tokens independent of the seed. Use `Color()` literals as specified.

| State | Label | Light Mode | Dark Mode | Shape |
|-------|-------|-----------|-----------|-------|
| system-confirmed | green check | `Color(0xFF2E7D32)` (Material Green 800) | `Color(0xFF66BB6A)` (Material Green 400) | Filled circle, 8px diameter |
| self-reported-only | blue circle | `Color(0xFF1565C0)` (Material Blue 800) | `Color(0xFF64B5F6)` (Material Blue 300) | Outlined circle, 8px diameter, 1.5px stroke |
| broken | red cross | `Color(0xFFC62828)` (Material Red 800) | `Color(0xFFEF9A9A)` (Material Red 200) | Filled circle with × glyph, 8px |

Today (pending, not yet rolled over): no dot. Render only the date number in `bodyMedium` weight 400.
Days with no data (before entry was created): empty cell, no dot, no number dimming.

## Screen Contracts

### Screen 1: `/checkin` — Daily Check-In Screen

**Route:** `GoRoute(path: '/checkin')` — added to `app_router.dart` per D-02

**Triggers:** reminder notification tap (NOTF-03 deep-link) AND Home cold-open when pending entries exist (D-01)

**Layout:**
```
AppBar: title "Daily check-in" (centerTitle: false)
Body: SingleChildScrollView, padding 16px horizontal
  Heading: "How did today go?" — titleLarge, weight 400
  SizedBox height 16
  For each pending entry (one row per entry):
    [entry row — see below]
    Divider
  SizedBox height 24
  FilledButton "Submit" — full width (minimumSize: Size.fromHeight(48))
    Disabled until at least one entry answered
  SizedBox height 32
```

**Entry row layout (per entry):**
```
Row, height ≥ 44px (touch-target minimum)
  Leading: app icon (AppIcon widget) or spa_outlined icon (habit), size 32px
  SizedBox width 12
  Expanded: Text(entry.displayName, bodyMedium, maxLines: 1, ellipsis)
  SegmentedButton<bool> with two segments:
    Segment(value: true, label: Text('Yes'))   — "I avoided it"
    Segment(value: false, label: Text('No'))   — "I used it"
    multiSelectionEnabled: false
    selected: {currentAnswer} or {} (unselected state)
```

**Empty state (all entries already answered — arrived via Home trigger):**
```
Center:
  Icon(Icons.check_circle_outline, size: 48, color: colorScheme.primary)
  SizedBox height 16
  Text("You're all caught up", titleMedium)
  SizedBox height 8
  Text("Check back tomorrow.", bodyMedium, color: onSurfaceVariant)
```

**Idempotency:** already-answered entries show their prior answer with the SegmentedButton locked (disabled). Submit button remains visible but shows "Done" label when all answered via prior path.

**No back-gesture block:** standard GoRouter back navigation allowed. Unanswered entries remain pending until next evaluation (D-04 all-day window).

### Screen 2: Home Streak Surface — Per-Entry Badge

**Widget:** inline metadata in `BlockListRow` trailing slot (Phase 2 `—` placeholder replaced)

**Badge format:** `🔥 {current} · best {longest}`

Exact rendering rules:
- `🔥` = Unicode U+1F525 character, rendered by system font at `labelSmall` size (14sp)
- Current count = integer, no suffix (day-suffix omitted from badge per D-14)
- Separator = ` · ` (space + middle-dot U+00B7 + space)
- `best` = lowercase literal
- Longest count = integer
- Day-0 / never-tracked: `🔥 0 · best 0` (no CTA copy, no hidden badge — D-15)
- Streak broken (current=0 after break): `🔥 0 · best {prior_longest}` — no strikethrough on the badge itself; strikethrough (`TextDecoration.lineThrough`) applies to the PRIOR count only on the day of detection (transitional state, reverts to standard format from the next day)

**Placement:** `trailing` slot of `ListTile` inside `BlockListRow`. Style: `tt.labelSmall?.copyWith(color: cs.onSurfaceVariant)` for the full badge string when streak=0 or unconfirmed; `tt.labelSmall?.copyWith(color: cs.onSurface)` when current > 0.

**Tap target:** the entire row tap routes to `/list/edit/:entryId` (existing Phase 2 behavior). No separate badge tap target — streak history is accessed via the entry detail screen that the row already routes to.

### Screen 3: Entry Detail — Streak History Section

**Host screen:** `EditEntryScreen` at `/list/edit/:entryId` (Phase 2 existing)

**New section added below the `ScheduleEditor` block and above the Save/Delete buttons:**

```
Divider
SizedBox height 16
Text("Streak history", style: titleMedium)
SizedBox height 12
GridView (NeverScrollableScrollPhysics, shrinkWrap: true)
  crossAxisCount: 7 (7 columns = Mon..Sun)
  childAspectRatio: 1.0
  mainAxisSpacing: 4
  crossAxisSpacing: 4
  children: last 30 days, oldest-first (top-left = 31 days ago, bottom-right = today)
  Each cell: _DayDot widget (see dot spec above in Color section)
SizedBox height 12
Text("{current} days · best {longest}", style: bodyMedium, color: onSurfaceVariant)
SizedBox height 4
Text("Streak breaks if you use this app over 5 min/day (change in Settings)",
     style: labelSmall, color: onSurfaceVariant)
SizedBox height 16
```

**Grey dot tooltip (incomplete-data):**
- Wrap grey dot cell in `Tooltip(message: "Tracking was off this day", child: _DayDot(...))`
- Tooltip is mandatory per D-07 — required for accessibility (grey cannot be distinguished from "no data" without it)

**Day dot widget spec:**
- Container: 24×24px, alignment: center
- Dot: 8px diameter `Container` with `BoxDecoration(shape: BoxShape.circle, color: ...)` or `BoxDecoration(shape: BoxShape.circle, border: Border.all(...))` per state
- For `broken` (red ×): overlay a `Text('×', style: TextStyle(fontSize: 8, color: red, fontWeight: FontWeight.w700, height: 1))` centered on the filled circle
- For `self-reported-only` (blue ○): outlined circle only (no glyph)
- For `incomplete-data` (grey —): outlined circle with `Text('—', style: TextStyle(fontSize: 8, color: grey, height: 1))`
- For today (pending): `Text(day.day.toString(), style: labelSmall, color: onSurfaceVariant)` only — no circle
- For empty (before entry creation): empty `SizedBox(width: 24, height: 24)`

### Screen 4: Reminder Settings Picker

**Host screen:** Settings screen (Phase 6 will add a dedicated settings route; Phase 5 may add a minimal inline picker in onboarding or accessible via a temp route). Per D-09, the picker is in Settings under a "Streak & Reminder" section.

**If Settings screen does not exist in Phase 5 scope:** add a `ListTile` in the app's existing AppBar menu or create a minimal `/settings/reminder` route. Decision deferred to planner — this spec covers the picker widget contract only.

**Widget contract:**

```
ListTile (settings list item):
  leading: Icon(Icons.notifications_outlined)
  title: Text("Daily reminder")
  subtitle: Text(_formatTime(hour, minute))  // e.g. "9:00 PM"
  trailing: Icon(Icons.chevron_right)
  onTap: showTimePicker(
    context: context,
    initialTime: TimeOfDay(hour: savedHour, minute: savedMinute),
    use24HourFormat: false,  // locale-driven; Android typically follows system
  )
```

**Default value:** `hour: 21, minute: 0` → stored as `21 * 60 + 0 = 1260` under `shared_preferences` key `reminder_hour_minute` (per D-09 / CONTEXT specifics).

**Post-pick behavior:** write new value to `shared_preferences`, cancel existing `AlarmManager` alarm, set new alarm. No confirmation dialog — the time picker IS the confirmation.

**Display format:** `DateFormat.jm()` from `intl` package (already in pubspec) — renders "9:00 PM" in en-US locale, "21:00" in 24h locales. Do NOT hard-code "AM/PM" string.

### Screen 5: NOTF-07 In-App Reminder Banner

**Condition:** `POST_NOTIFICATIONS` permission denied.

**Placement:** top of `HomeScreen.body`, BELOW the existing tracking-offline `HealthCheckBanner` and ABOVE the `AvoidedTodayCard`. Stack order (top-to-bottom on screen):
1. `HealthCheckBanner` (tracking-offline, Phase 3) — higher priority
2. Reminder-off banner (Phase 5 addition, only visible when tracking-offline is NOT showing OR shown second)

Per D-12: banner stack order is tracking-offline > reminder-off. Both can be visible simultaneously when both conditions are true.

**Widget spec (inline in `HomeScreen`, not a new named widget — pattern-copy from `HealthCheckBanner`):**

```
Material(color: _amberBgLight / _amberBgDark)
  InkWell(onTap: _tapToFix)
    Padding(horizontal: 16, vertical: 8)
      Row:
        Icon(Icons.notifications_off_outlined, size: 16, color: fg)
        SizedBox width 8
        Expanded:
          Text("Reminder is off — tap to fix",
               bodyMedium, fontWeight: w500, color: fg)
```

No expand/collapse toggle (simpler than `HealthCheckBanner` — reminder-off has one action path only, no multi-reason expansion needed).

**Tap behavior:**
- If `shouldShowRequestPermissionRationale` == false (user chose "Don't ask again"): route to `ACTION_APP_NOTIFICATION_SETTINGS` via `app_settings` or `url_launcher` intent
- Otherwise: route to in-app rationale screen + `requestPermissions` re-prompt (same earned-prompt screen from NOTF-06)

**No dismiss button.** Banner disappears only when `POST_NOTIFICATIONS` is granted (matches Phase 3 `HealthCheckBanner` pattern exactly).

**Color tokens:** identical to `HealthCheckBanner`:
- Light: bg `Color(0xFFFFF3CD)`, fg `Color(0xFF856404)`
- Dark: bg `Color(0xFF3D2E00)`, fg `Color(0xFFFFD966)`

## Interaction Contracts

### Check-In Flow

1. Submit button is disabled (`FilledButton` with `onPressed: null`) until at least one Yes/No answer is recorded.
2. On Submit: write all answered rows to `daily_checkins` in a single Drift transaction. Unanswered rows are NOT written (they remain pending until midnight rollover per D-04).
3. After successful write: `context.go('/')` — return to Home.
4. On write error: show `SnackBar` with error copy above. Do not pop the screen.
5. Idempotent: re-entering `/checkin` after partial submit shows already-answered entries with locked `SegmentedButton` (disabled). Already-answered entries render their stored answer.

### Streak Badge Tap

- The entire `BlockListRow` routes to `/list/edit/:entryId` on tap (existing Phase 2 behavior).
- No separate tap target on the badge text itself.
- On entry detail screen, the new "Streak history" section is immediately visible below the schedule editor (no additional tap required).

### Grey Dot Tooltip

- `Tooltip` widget wraps the dot cell.
- On Android, tooltip appears on long-press (Flutter default behavior). This is acceptable — the copy `"Tracking was off this day"` does not gate any action; it is informational only.
- Do not use a custom popup — standard `Tooltip` is sufficient.

### Reminder Time Picker

- `showTimePicker` returns `TimeOfDay?` — null if user dismissed. On null: no-op (retain prior value).
- On non-null: persist immediately, re-arm alarm before returning.

### Permission-Denied Banner (NOTF-07)

- Banner visibility is driven by a Riverpod provider watching `POST_NOTIFICATIONS` status.
- `AnimatedSwitcher(duration: Duration(milliseconds: 200))` wraps both banners in `HomeScreen` (matching existing `HealthCheckBanner` animation).
- Banner state is re-evaluated on every `AppLifecycleState.resumed` (user returning from Settings — same `WidgetsBindingObserver` pattern as Phase 3).

## Accessibility Contract

- All 4 day-status dot states must have semantic labels for screen readers:
  - green: `Semantics(label: "{date} — avoided, system confirmed")`
  - blue: `Semantics(label: "{date} — avoided, self-reported")`
  - red: `Semantics(label: "{date} — streak broken")`
  - grey: `Semantics(label: "{date} — incomplete data")`
- Check-in `SegmentedButton` Yes/No: Flutter `SegmentedButton` provides ARIA role natively. No additional wrapping needed.
- Touch targets: ≥ 44×44dp on all interactive elements (Yes/No toggles, dot cells with tooltip, banner tap area).
- Streak badge is decorative text — no separate semantic label needed (screen reader reads the text directly).
