## Spacing Scale

All spacing values are multiples of 4. Specified in logical pixels (dp/pt), not physical pixels.

| Token | dp value | Flutter constant | Usage |
|-------|----------|-----------------|-------|
| space-4 | 4 dp | `const SizedBox(height: 4)` / `EdgeInsets.all(4)` | Icon-to-label gap, chip internal padding |
| space-8 | 8 dp | `const SizedBox(height: 8)` | Between related elements, subtitle gap |
| space-12 | 12 dp | `const SizedBox(height: 12)` | List tile internal vertical padding |
| space-16 | 16 dp | `const SizedBox(height: 16)` | Default horizontal page margin, form field spacing |
| space-24 | 24 dp | `const SizedBox(height: 24)` | Section separator, between major form groups |
| space-32 | 32 dp | `const SizedBox(height: 32)` | Large gap between unrelated sections |
| space-48 | 48 dp | `const SizedBox(height: 48)` | Minimum touch target height (see below), bottom CTA padding |
| space-64 | 64 dp | `const SizedBox(height: 64)` | Page-level bottom padding to clear FAB/nav |

**Touch target minimum:** 48 × 48 dp on all tappable elements. Apply `constraints: const BoxConstraints(minWidth: 48, minHeight: 48)` or use `Material` + `InkWell` which auto-expands hit area.

**List row height:** 64 dp. Fixed. Do not use dynamic height for home list rows. (CONTEXT.md: "Compact row (~64 dp).")

**Exceptions:**
- Weekday chips (M T W T F S S): 36 dp height is acceptable as each chip pair total touch width is ≥48 dp due to adjacent taps; but add `minimumSize: Size(36, 36)` + `padding: EdgeInsets.symmetric(horizontal: 4, vertical: 0)` on `FilterChip`.
- Permission step static screenshot images: full-width, unconstrained height (aspect-ratio box).

## Typography

Flutter M3 typography roles mapped to concrete values. All sizes are sp (scale-independent pixels).

| M3 Role | Flutter TextTheme key | Size | Weight | Line Height | Usage |
|---------|----------------------|------|--------|-------------|-------|
| Display | `displaySmall` | 36 sp | w400 (Regular) | 1.2 | Welcome headline "Build your Not-To-Do list" |
| Headline | `headlineSmall` | 24 sp | w400 (Regular) | 1.2 | Permission step headline, section headers |
| Title | `titleMedium` | 16 sp | w500 (Medium) | 1.3 | App bar title, list section labels |
| Body | `bodyLarge` | 16 sp | w400 (Regular) | 1.5 | Permission rationale body text, form field hints, reason note |
| Body small | `bodyMedium` | 14 sp | w400 (Regular) | 1.5 | Reason snippet (home list row, ellipsized 1 line), subtitle copy |
| Label | `labelLarge` | 14 sp | w500 (Medium) | 1.2 | Button labels (FilledButton, OutlinedButton, TextButton) |
| Caption | `labelSmall` | 14 sp | w400 (Regular) | 1.3 | Char counter (past 400 chars), "already added" subtitle, streak placeholder "—" |

**Rules:**
- Use exactly these 4 sizes: 36 / 24 / 16 / 14. Do not introduce 11, 12, 13, 15, 18, 20, or 28.
- Use exactly 2 weights: Regular (w400) and Medium (w500). Do not use w600, w700 (Bold), or w300.
- Body text always at 1.5 line-height. Headings always at 1.2 line-height.
- Ellipsize overflow with `TextOverflow.ellipsis` and `maxLines: 1` on reason snippets and app names in list rows.
- Char counter text: show only when `reasonNote.length >= 400`. Display as "400/500", "401/500", …, "500/500". At 500 chars, prevent further input (hard cap).
- `labelSmall` is sized at 14 sp (not the M3 default 11 sp) — executor MUST override `TextTheme.labelSmall.fontSize` in ThemeData. The role still distinguishes labelSmall from `bodyMedium` semantically (compact metadata: char counter, "already added" subtitle, streak placeholder); both share the 14 sp size but `labelSmall` is the Caption slot.

| `surfaceContainer` | `Theme.of(ctx).colorScheme.surfaceContainer` | Home list row background, cards, bottom sheet |
| `surfaceContainerHighest` | `Theme.of(ctx).colorScheme.surfaceContainerHighest` | Disabled/greyed-out app entries in picker |
| `primary` | `Theme.of(ctx).colorScheme.primary` | Primary CTA buttons (FilledButton), active chip border, progress indicator |
| `onPrimary` | `Theme.of(ctx).colorScheme.onPrimary` | Text/icon on primary-colored surfaces |

| `outlineVariant` | `Theme.of(ctx).colorScheme.outlineVariant` | Subtle dividers, disabled borders |

### 60 / 30 / 10 distribution

**Distribution:** ~60% `surface` (page backgrounds), ~30% `surfaceContainer` / `onSurface` (rows + body text), ~10% `primary` (CTAs + active states). The home list, picker, and edit pages are the primary venues for this split — `surface` dominates the empty space, `surfaceContainer` for list rows + cards, `primary` reserved for the single CTA per screen.

### Accent reserved for (10% rule)

The `primary` color role is reserved for exactly these elements:
- The single FilledButton CTA on each screen (Get Started, Continue, Save habit, Save changes, Open Settings)
- Active weekday chip fill (selected state)
- Focus ring on OutlinedTextField
- Stepper progress indicator (permission funnel dots)

Do NOT use `primary` for: informational icons, section headers, streak placeholder, health-check banner, or any static text.

### Destructive (delete affordance)

Use `colorScheme.error` for:
- Delete button on the entry detail/edit page (text color + border)
- No other uses in Phase 2

### Health-check banner color

**Amber / warning — NOT `colorScheme.error`.** Use a fixed amber tone that works in both light and dark:
- Light mode: background `Color(0xFFFFF3CD)`, text/icon `Color(0xFF856404)` (WCAG AA on the amber bg)
- Dark mode: background `Color(0xFF3D2E00)`, text/icon `Color(0xFFFFD966)`
- These are fixed values for the banner only — not in the main M3 ColorScheme seed.

### Seed color and static fallback

| | Light mode | Dark mode |
|-|-----------|-----------|
| Seed color | `Color(0xFF2D6A4F)` — deep forest green. Quiet, not playful. Adult self-control tone. | Same seed, `brightness: Brightness.dark` |
| Static fallback palette (Android 10/11, no dynamic color) | `ColorScheme.fromSeed(seedColor: Color(0xFF2D6A4F), brightness: Brightness.light)` | `ColorScheme.fromSeed(seedColor: Color(0xFF2D6A4F), brightness: Brightness.dark)` |
| Dynamic color (Android 12+) | `DynamicColorBuilder` wraps `ColorScheme.fromSeed` fallback; if `lightDynamic != null` use it, else fall back to seed | Same pattern |

**Implementation note:** Use the `dynamic_color` package (`^1.7.0`) to detect Material You palette on Android 12+. If `lightDynamic == null` (Android 10/11), fall through to the static seed. The executor must wire this in `app.dart` around the `MaterialApp`.
